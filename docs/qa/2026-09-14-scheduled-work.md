# 예약 업무 개발 검증

기준: `7a309eb` / schema 55. 대상: `codex/scheduled-work`의 변경 파일만.

## 완료한 검증

- 프런트: 52개 파일, 303개 테스트 통과. TypeScript, Prettier, Vite production build 통과.
- 서버: storage / API / Agent 단위 테스트 통과. 신규 API 인증 guard 추가 테스트 통과. Clippy `--all-targets -- -D warnings`, Cargo fmt 및 API·Agent 빌드 통과.
- 모바일 빌드 설정 검사와 Mobile MCP 유틸 테스트 6개 통과. 운영 앱에 개발 설정을 설치하지 않음.
- PostgreSQL 17 격리 DB에서 기존 migration 55까지 적용 후 56으로 실제 업그레이드. 통합 테스트 3회 수행, 마지막 재검증 통과.
- 동시 실행자 2개가 같은 예약을 조회해도 한 번만 처리. 수동 실행 요청 ID 재전송도 실행·전송 큐를 중복 생성하지 않음.
- 미리보기 이후 완료된 일 제외, 변경된 담당자 반영, 오늘/내일 자정 경계 구분, 참고 링크·검토된 상세와 한국어 마감 시각 유지.
- 오후 확인은 오전에 실제 안내한 일만 재조회. 오전 안내 이후 추가된 일은 포함하지 않음.
- 일시정지는 미전송 큐를 취소. 비활성 연결이어도 정지 가능. 한 번 건너뛰기와 2시간 초과 지연 시 다음 미래 예약으로 이동.
- 멘션 매핑 누락은 실패로 기록하고 알림 생성. 외부 전송 실패는 실행 이력에 반영하며 알림을 한 번만 생성. 기존 push 정리·claim 경로를 통과함.
- 대상이 없는 조회는 실패가 아닌 건너뜀으로 기록.
- 자연어 처리의 구조화된 예약 명령은 검증된 업무 공간에만 초안을 생성하며 자동 활성화하지 않음. 잘못된 시각·타 소유 공간 거부.
- 화면: 데스크톱에서 새 예약 작성 → 프로젝트 선택 → 미리보기 → 활성화 → 즉시 실행 → 상세 이력 → 한 번 건너뛰기 → 정지 확인.
- 모바일 390×844에서 편집·미리보기·저장·재개·즉시 실행·이력 확인. Escape로 닫을 때 미저장 확인 표시와 돌아가기 후 내용 보존 확인.
- 360×800에서 문서 너비 360, dialog `clientWidth=scrollWidth=342`로 가로 넘침 없음. 요일 버튼은 44×44, 4+3열. 390에서는 44×44 한 줄. 임시 viewport 복원.
- 비밀값 검사 통과. 운영 원문·연결 키를 개발 DB에 복사하지 않음.

## 발견하고 수정한 항목

1. 외부 전송 최종 실패 시 앱 알림 누락 → 실행 결과 갱신과 실패 알림을 한 트랜잭션으로 저장, 중복 알림 회귀 검증.
2. 실행 시 멘션 디렉터리 변경 경쟁 → 연결 레코드 공유 잠금으로 검증과 전송 스냅샷 일치.
3. 담당자 필터의 쉼표 입력 소실 → 입력 문자열과 정규화된 필터 분리.
4. 실행 이력 추가 페이지가 주기 새로고침으로 사라짐 → 로드한 과거 페이지 유지. 해결된 과거 실패가 계속 표시됨 → 예약별 최신 결과만 실패 표시.
5. 모바일 요일 버튼 불균형, 목록 복귀 시 미저장 내용 소실 → 작은 화면 레이아웃과 미저장 확인·포커스 처리 보완.
6. 홈 알림이 일정 ID로 조회되는 문제 → 홈 알림은 홈으로 이동. 기존 Android 알림 타입 계약을 유지하도록 서버 wire 값 호환 처리.
7. 신규 route 추가에 따른 OpenAPI golden path 테스트 실패 → 실제 공개 경로 계약에 5개 route 반영 후 재검증.
8. Docker 디스크 공간 부족 → 다른 프로젝트 데이터를 지우지 않고 이번 검증 DB만 tmpfs에 생성.

## 품질 게이트

- Backend harness는 이번 migration과 실제 package scripts의 격리 복사본에 실행해 통과. 이 오래된 정규식 harness가 Rust를 검사하지 않는 한계는 실제 Rust formatter / lint / test / build와 수동 인증·검증·로그 검토로 보완함.
- UX Writing 스킬의 WRITING.md / TERMS.md 기준을 적용해 문구·상태·복구 행동을 검토함. 초안·전송 중·처리 완료를 구분함.
- UX 정규식 도구의 TSX 검사 67개 지적은 코드 식별자(`null`, `undefined`, `token`, error 필드명), HTML `placeholder` 속성, section 접근성 이름을 문구·CTA로 해석한 오탐임을 각 줄에서 확인함. 자동 도구 전체 통과로 보고하지 않음. 실제 오류 문구에는 연결·멘션 확인 또는 새로고침·재시도를 안내함. 이 검토는 품질 실패의 승인 예외가 아님.
- 디자인·인터랙션은 이번 컴포넌트의 토큰, 상태, 터치·키보드, 축소 동작과 cleanup만 점검함. 관련 없는 전체 UI는 재검수하지 않음.

## 개발 검증 밖의 확인

- 실제 연결 AI 모델이 사용자의 자연어로 초안을 생성하는 end-to-end 실행은 하지 않음. 구조화된 명령 계약과 저장 동작을 검증함.
- 실제 고객 Google Chat 채널 전송과 물리 기기 FCM 도착은 시험하지 않음. 기존 provider 전송 경로와 격리 큐/실패/멘션 계약을 검증함.
- 생산 배포 결과, 서명된 앱 설치와 운영 네트워크 확인은 인프라 담당 배포 보고서에서 별도로 기록함.

## 정리 범위

검증 종료 후 이번 tmpfs DB 컨테이너, 개발 API·Vite 프로세스, 임시 키 디렉터리, scoped harness 디렉터리, 이 worktree의 node_modules·dist를 제거한다. 공용 target 전체와 타 프로젝트 Docker 자원은 삭제하지 않는다. 이번 프로젝트에서 다시 생성한 API·Agent·storage 개발 패키지 산출물만 cargo clean으로 정리한다. 소스·테스트·운영 복구 백업은 보존한다.
