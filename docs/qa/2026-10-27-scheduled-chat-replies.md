# 기존 회사 연결의 예약 완료 답글 — 개발 검증

이 문서는 완료 답글 수집 기반의 첫 검증 기록이다. 이후 사용자 요청으로 즉시 완료를 확인 대기 방식으로 대체했다. 최신 계약과 검증은 `2026-10-27-completion-review-approval.md`를 따른다.

브랜치 `codex/scheduled-chat-completion`, base `567f6dc`.

## 변경 범위

- 앞서 미배포 상태였던 별도 Chat 앱 런타임·서비스 계정 설정·공개 콜백·Compose overlay를 제거했다.
- 기존 회사 OAuth의 읽기/전송 권한을 재사용한다. 완료 답글 옵션을 켠 예약만 회사 사용자 이름으로 전송하고, 기존 웹훅 예약은 바꾸지 않는다.
- 할 일별 OS 코드, 현재 담당자 Google ID, 정확한 알림 스레드, 소유자/계정/프로젝트/활성 연결, 일감 버전을 확인한다.
- 명령은 첫 줄 `완료 T-번호`, 선택적 완료 답글은 다음 줄이다. AI로 일반 대화를 완료 요청으로 추측하지 않는다.
- 완료/변경 스트림/원본 CS 답글/ITSM 큐/명령 영수증을 원자적으로 저장하고 결과 답글은 별도로 재시도한다.
- 이미 완료한 일·동시 요청·같은 메시지 재수집·재개한 일감·하위 미완료 작업을 보호한다.
- 알림 스레드를 일반 업무 분석에서 제외한다. 전송 응답 저장 전에 들어온 답글은 스레드별 추가 조회로 복구하고, 먼저 들어왔던 미승격 알림 대화만 신규 업무에서 정리한다.

DB 테스트는 `bash scripts/test-scheduled-chat.sh`로 이번 작업의 격리 컨테이너/빈 DB만 사용한다. 63→64 및 migrate 재실행을 검사하고 테스트 후 컨테이너를 정리한다.

신규 DB 계약에서 확인한 항목:

- 읽기/전송 권한이 포함된 기존 회사 계정과 프로젝트 연결, 기존 웹훅의 담당자 명단 재사용
- 티켓 없는 일에도 코드 발급, 미리보기/전송에 포함, 내부 버전 snapshot은 공개 응답에서 제외
- 전송 receipt의 worker/attempt fence, 회사 대화방의 실제 메시지·스레드 이름 저장
- 다른 스레드/잘못된 번호/발신자 누락/같은 표시 이름의 다른 사람 요청 차단
- 일반적인 “완료했습니다” 문장을 자동 완료하지 않음
- 변경된 일감의 오래된 알림 차단, 열린 하위 일이 있으면 완료 차단
- 두 담당자 동시 요청과 재수집에도 완료/CS 답글/ITSM 큐가 한 번만 생성됨
- 선택적 완료 메모 저장 및 빈 메모 완료 정상
- 늦게 등록된 스레드의 보충 조회 대상이 일반 수집 커서와 독립적이며 완료 표시는 명시적으로만 저장
- 알림 답글이 먼저 pending inflow로 수집됐더라도 정확한 해당 글만 제외하고 이미 승격된 일은 보존
- 결과 답글 재시도/오래된 worker 차단, 완료한 일 재개 후 과거 명령 차단
- source 비활성화 후 전송 context 철회, migration 멱등성

## 화면 확인

실제 `ScheduledWorkPanel`에 격리된 모의 응답을 주입했다. 실제 계정·Chat 메시지는 변경하지 않았다.

- Chrome 1440×1000 / 390×844에서 생성 → Google Chat → 프로젝트 연결 → 완료 답글 옵션 → 회사 계정 대화방 → 미리보기 → 활성화 저장.
- `replyCompletionSourceId` 저장 확인, 폐기한 `chatCompletionSourceId`가 저장되지 않음.
- 선택된 회사 계정 표시, 설명·완료 명령 안내, 가로 넘침 없음, page error 없음.
- 연결 미준비/대화방 없음의 비활성 안내, 닫기·변경 버리기, 완료한 일만 안내하는 조건에서 완료 답글 옵션 해제를 확인했다.
- 새 UI는 기존 배치를 바꾸지 않고 예약 폼 안에 추가했다. 모바일에서 긴 계정은 별도 줄로도 표시한다.
- 화면 캡처: `/tmp/jimin-scheduled-reply-1440.png`, `/tmp/jimin-scheduled-reply-390.png`.
- Android 실기기/운영 Mac 앱 테스트나 설치는 하지 않았다. 모바일 반응형 확인과 구분한다.

## 품질 게이트

- Backend Ultrawork harness는 `apps/api` 범위에서 통과(지원 확장자 1파일). Rust 검증을 대신하지 않아 Cargo·DB 검증을 따로 수행했다.
- UX Writing harness는 신규 `scheduledChat.ts`에 통과. Rust 문구는 직접 확인했다.
- 실행 중 발견한 컴파일/Clippy 및 테스트 helper lifetime 문제를 수정한 뒤 재실행했다. 미해결 실패를 성공으로 표시하지 않는다.
- 요구사항에 따라 별도 앱 전용 코드와 미배포 migration을 대체했다. 이전 migration64를 운영에 적용한 적은 없다.

## 미실행

운영 계정으로 실제 메시지 전송·완료 답글 감지·결과 답글·외부 Redmine 반영은 미실행이다. 운영 배포/DB migration/기기 설치도 하지 않았다. 실제 연결의 승인 scope와 네트워크 상태는 운영 테스트 시 별도로 확인해야 한다.
