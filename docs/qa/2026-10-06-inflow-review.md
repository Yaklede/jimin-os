# 업무 요청 분리 및 제외 사유

## 범위

- 새 업무 요청, 기존 일감 업데이트, 확인한 대화를 분리한다.
- 확인 상태는 서버에 저장하며 제외 상태와 구분한다. 새 외부 답글이 오면 다시 확인 대상이 된다.
- 업무 아님을 선택하면 사유를 입력할 수 있다. 원문에 사유 답글을 남기는 것은 기본 꺼짐인 명시적 선택이다.
- 제외와 답글 발송은 같은 트랜잭션에서 결정/대기열을 저장한다. 발송 실패는 제외를 되돌리지 않으며 재시도한다.
- 운영 데이터로 실제 Chat 발송 테스트를 하지 않는다.

## 체크리스트

- [x] 요청 입력 검증, 소유권/프로젝트 경계, 버전 충돌
- [x] 확인 상태 재조회, 새 답글과 확인 시점 경계
- [x] 사유 저장, 답글 선택, 발송 실패/재시도/중복 방지
- [x] API 및 저장소 테스트, 타입 검사, 린트, 빌드
- [x] 데스크탑/모바일 화면과 키보드 접근성
- [ ] 운영 DB 백업/복원 확인, migration 57 적용, readiness 검증
- [ ] 운영 desktop 설치, 실기기 연결 여부 확인

## 검증 중 발견 및 수정

1. 새 저장소 테스트에서 수집 결과를 조회 모델로 취급했다. 수집은 acknowledgement ID를 반환하므로 저장 후 조회하도록 수정했다.
2. 새 함수를 추가하면서 Rust 문서/길이 린트가 실패했다. 오류 계약을 추가하고 원자적 트랜잭션/분기 함수에 사유 있는 범위 예외를 명시했다.
3. 두 홈 구역이 같은 접근성 제목 ID를 사용했다. 신규/기존 구역별로 고유 ID를 적용했다.
4. 새 폼의 색상 변수가 실제 토큰과 달랐다. 기존 text/surface/border 토큰을 사용하도록 수정했다.
5. 일감 승격 helper의 반환 SELECT에 새 필드가 누락되어 DB 통합 테스트가 실패했다. 모든 조회/변경 반환 모델을 일치시켜 승격 회귀를 복구했다.
6. 기존 DB trigger는 확인 상태 변경을 version 증가 대상으로 보지 않았다. 새 확인/사유/답글 상태를 버전 계약에 포함하고 기기 간 변경 이벤트를 저장하도록 수정했다.

## 배포 및 롤백

- 신규 필드는 nullable/default로 기존 데이터와 호환된다. schema 57을 기대하는 API/Agent를 함께 배포한다.
- 배포 전 backup을 복원해 migration dry-run 및 readiness를 확인한다.
- 실패 시 앱/이미지는 이전 릴리스로 되돌린다. schema 57은 이전 schema 56 binary readiness와 호환되지 않으므로 DB까지 이전 backup으로 복원해야 한다. 전환 이후 새 사용자 입력이 있는 경우 복원 전 별도 보존 및 사용자 확인이 필요하다.
- PostgreSQL/회의 전사 이미지와 외부 계정/연결 설정은 변경하지 않는다.

## 검증 결과

- PostgreSQL: 실제 격리 DB 52개 시나리오 모두 통과. 신규 확인/제외/답글 실패·재시도와 기존 일감 승격 회귀를 포함한다.
- API unit: 113개 통과. 변경된 응답의 확인 상태 합산과 기존 인증 guard를 포함한다.
- Desktop unit: 311개 통과. 신규/기존 구역, 기본 접힘, 요청 body 선택을 포함한다.
- TypeScript, Rust formatter/Clippy, 운영 web build 및 운영 서버 origin 검사 통과.
- 공용 컴포넌트를 별도 dev 샘플에서 렌더링해 desktop 및 모바일 390×844 요청 너비를 확인했다. 실제 content 너비 375/scrollWidth 375로 가로 넘침 없음. 사유 입력, 기본 꺼진 답글 선택, 제외 후 다음 항목 선택을 확인했다.
- 실제 운영 Chat 발송은 미실행. 발송 요청 ID 안정성과 실패 후 제외 보존은 DB 통합 테스트로 확인했다.
- UX 자동 검사에는 기존 코드의 null/undefined, textarea placeholder 속성, error 변수명을 사용자 문구로 잘못 인식하는 오탐이 있다. 기존 보고서 상태의 ‘생성 실패’도 신규 변경 범위가 아니다. 신규 공개 문구는 별도 추출 검증과 수동 계약 확인으로 검토했다. 자동 검사 전체 통과로 보고하지 않는다.
- Backend 정규식 harness는 Rust 파일을 지원하지 않아 신규 SQL에만 적용됐다. Rust 실제 검증은 Clippy/API/DB 테스트로 보완했다.
