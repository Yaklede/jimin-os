# 원문 Chat 복구와 맥 업무 알림 진단 — 2026-10-08

## 범위와 상태

- 작업 브랜치: `codex/holiday-home-workflow`, 기준 commit `3b193e1`.
- N3/C3 중 원문 체크 표시·담당자/마감 답글·업무 아님 사유 답글의 부분 실패 복구를 구현했다. 배정 웹훅과 기기 알림의 통합 복구까지 완료한 것은 아니다.
- 개발 예시 화면: `http://127.0.0.1:1423/`. 재시도는 예시 데이터만 바꾸며 실제 Chat에 보내지 않는다.
- 운영 서버에는 알림 진단을 위한 읽기 전용 조회만 했다. 운영 데이터, 시스템 알림 설정, 운영 앱과 개인 휴대폰은 변경하지 않았다. Now Bar는 사용자 답변에 따라 제외했다.

## 발견한 문제와 변경

1. 홈 API가 처리된 유입 이력을 비워 반환해 저장한 일감의 원문 반영 실패를 확인할 수 없었다. 기존 응답 필드에는 미완료 원문 반영만 반환하고, 완료된 이력은 계속 제외한다. 읽기는 소유자 범위로 제한하고 200건으로 제한한다.
2. 수동 재시도가 이미 성공한 원문 체크와 답글 시각까지 초기화했다. 성공 기록과 저장한 일감을 유지하고 남은 단계만 다시 요청하도록 수정했다.
3. 홈에서 재시도한 뒤 프로젝트 목록만 갱신하던 경로를 수정했다. 홈 응답도 다시 읽으며 동일 대화의 최신 전달 상태를 반영한다.
4. 최신 성공 버전과 오래된 실패 버전이 함께 있으면 먼저 최신 버전을 선택한 뒤 복구 대상 여부를 판단한다.
5. 홈은 기본으로 접힌 복구 영역을 제공한다. 개별 단계의 완료·처리 중·실패를 색상뿐 아니라 아이콘과 글로 표시한다. 권한, 연결, 원문 삭제 등 원인별 다음 행동을 안내한다. 실패한 행에 다시 요청 실패 안내가 남고, 처리 중에는 중복 재시도 버튼을 숨긴다.

## 검증

- 프런트엔드: 74개 파일의 테스트 463개, TypeScript, 현재 변경 대상 Prettier 검사, 일반 웹 빌드 통과.
- Rust: API/저장소 단위 테스트 201개 통과. API/저장소 all-targets Clippy의 경고를 오류로 처리한 검사와 formatter, API release 빌드 통과.
- PostgreSQL: 각 시나리오별 새 데이터베이스에서 54개 격리 회귀 통과. 체크 성공/답글 실패 상태 보존, 다른 소유자의 조회·재시도 차단, 재시도 후 실패 목록 제거, 완료된 단계 재전송 방지, 사유 답글 복구를 포함한다. DB 환경이 없는 기본 테스트 생략과 구분해 실제 실행했다.
- 실제 개발 브라우저: 데스크톱 기본 화면, 390×844, 320×480. 복구 영역 펼치기/접기, Enter/Space 동작, 첫 재시도 실패 안내, 두 번째 성공 후 행 제거, 사유 답글 재시도, 저장된 일감 유지, 처리 중 재시도 미표시를 확인했다. 행 제거 후 남은 영역의 summary로 포커스가 돌아왔다.
- 모바일 웹의 재시도/일감 열기 버튼 높이는 44px이며 가로 넘침이 없었다. 현재 화면에서 콘솔 오류·경고는 없었다.
- Android 개발 APK는 별도 `io.jimin.os.dev`임을 확인해 `JiminOS_Test_API_36` / `emulator-5554`에만 설치하고 실행했다. 이번 실행에서는 화면 제어 도구가 에뮬레이터 창을 선택할 수 없어 네이티브 터치/뒤로가기 검증은 완료하지 못했다. 모바일 웹 검증을 네이티브 검증으로 대신 기록하지 않는다.
- 실제 Google Chat에 체크·답글을 보내는 운영 전송 검증, 맥에서 타인이 보낸 새 업무의 실제 알림 표시, 라이트 모드의 별도 화면 확인은 미실행이다.

## 검사 중 실패와 남은 검사 제한

- 첫 Rust 통합 테스트 컴파일에서 변경 전 메서드 이름이 테스트에 남아 있었고, 첫 Clippy에서 홈 핸들러 길이 제한에 걸렸다. 참조와 응답 조립 함수를 수정한 뒤 재실행해 통과했다.
- Android 빌드의 최초 시도는 pnpm의 자동 의존성 재설치와 Java 실행 환경 때문에 실패했다. 다른 작업의 공유 의존성 폴더를 재설치하지 않고 이 빌드에서만 검증된 기존 실행 파일과 설치된 JBR을 사용해 최종 빌드를 통과했다. 저장소 빌드 설정은 바꾸지 않았다.
- Backend Ultrawork 정적 검사에는 현재 대상과 package scripts만 복사한 격리 디렉터리를 사용했다. 검사기는 Rust 파일 확장자를 검사하지 않아 실제 스캔 1건은 package 설정이었다. 이 결과를 Rust 코드 안전성 증거로 해석하지 않으며, 인증 guard·소유자 조회·버전 검사·SQL bind·비밀정보 로깅 여부는 수동 확인 및 Rust/DB 테스트로 검증했다.
- UX Writing 스킬로 새 상태와 오류의 다음 행동을 점검했다. 5개 대상 정적 검사의 81건 경고는 코드 `null`/`undefined`, `failed` 식별자, 짧은 상태 라벨, 여러 줄 문구 키, 기존 placeholder 속성 등을 문구로 판단한 결과를 포함한다. 공개 화면 문구를 직접 확인했다. 정적 검사 전체 통과나 사용자 승인 예외로 기록하지 않는다.

## 맥 진단의 한계와 다음 재현

위 조건이 현재 알림을 만들지 않는 이유는 확인했지만, 사용자가 경험한 누락 건의 최종 원인은 아직 확정하지 않았다. 누락된 대화 시간과 앱 실행/종료 상태를 질문했다. 타인이 보낸 새 대화가 누락됐다면 해당 시간의 분석 완료·알림 후보 여부를 따로 확인해야 한다.
