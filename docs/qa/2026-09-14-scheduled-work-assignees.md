# 예약 업무 공동 담당자 회귀 검증

## 원인과 수정 범위

운영 릴리스 `7aab67a`에서는 일감의 `assignee_name` 전체 문자열을 멘션 이름 한 개로 비교했다. `송인준, 김경주`가 각각 등록돼 있어도 미등록 멘션으로 판정했다. 담당자 필터도 전체 문자열 일치만 확인했고, 안내에는 첫 이름 앞에만 `@`를 붙였다.

예약 업무의 미리보기·저장 검증·실행·후속 확인에서 같은 담당자 해석을 사용하도록 수정했다. 쉼표로 나누고 앞뒤 공백, 빈 항목, 중복을 제거한다. 이름별 정확한 일치로 필터링하며 공동 일감의 ID와 본문은 중복하지 않는다. 그룹 제목에는 각 이름마다 멘션을 붙인다. 일감 저장값, API 요청/응답 구조, DB schema 56은 변경하지 않는다.

## 재현 및 재검증

- 수정 전 격리 PostgreSQL에서 사용자와 동일한 오류를 재현했다: `멘션할 사람을 연결에서 먼저 등록해 주세요: 송인준, 김경주`.
- 수정 후 같은 회귀 테스트와 기존 schema 55 → 56 예약 생명주기 테스트가 통과했다.
- 공백 유무, 앞뒤 공백, 중복 이름, 끝의 쉼표를 포함한 공동 담당자 미리보기에서 경고가 없고 두 멘션·일감 한 건이 나온다.
- 두 사람 중 어느 한 명만 필터로 선택하거나 두 명 모두 선택해도 공동 담당 일감은 한 번만 포함된다. 이름의 일부로는 일치하지 않는다.
- 활성 예약 저장 → 오전 실행 → DB 전송 큐의 두 멘션·등록 명부 스냅샷·마감 시각 → 후속 확인을 검증했다.
- 한 명이 실제로 미등록이면 그 이름만 경고하며 활성화는 계속 차단한다. 멘션을 끄면 이름은 안내하되 멘션하지 않는다.
- 미정·빈 담당자와 단일 담당자, 원문 내 임의 멘션 중립화 동작을 유지한다.
- Google Chat 최종 전송 데이터에서 두 이름이 각각 `<users/...>`로 변환되는 단위 테스트를 추가했다. 실제 고객 채널로 HTTP 요청을 보내지는 않았다.

## 품질 게이트

- `cargo fmt --all --check` 통과.
- API·Agent·storage `cargo clippy --all-targets -- -D warnings` 통과. 새 테스트의 빈 문자열 생성 스타일 지적 1건을 수정하고 다시 검사했다.
- API·Agent·storage 단위 테스트: 276개 통과 (Agent 81, API 112+1, storage 82).
- 전체 예약 PostgreSQL 회귀 테스트 통과. 실제 운영 데이터·연결 키는 사용하지 않았다.
- API·Agent build 통과. Backend harness는 변경 파일과 실제 package scripts의 격리 복사본에서 통과했다 (Rust 파일은 도구 검사 대상이 아니며 아래 범위 한계를 적용).
- 인증·소유권 검증, 요청 검증과 OpenAPI route 계약은 변경하지 않았고 기존 회귀 테스트로 확인했다. 신규 migration·민감 로그·실제 인증키는 없다.
- 화면 코드 변경이 없으므로 데스크톱·모바일은 같은 서버 수정이 적용된다. 이번 작업에서 UI 재설치나 실제 기기 검증을 완료한 것으로 보고하지 않는다.

## 검증 도구 범위

Backend/UX Writing 정규식 도구는 Rust 확장자를 검사하지 않는다. UX 도구에 Rust 파일을 직접 지정하면 이전 manifest로 되돌아가는 한계를 확인했다. 이전 화면 파일의 지적을 이번 수정 결과로 취급하지 않는다. 이번 Rust 동작은 실제 Rust 검사와 DB 회귀 테스트로 확인하고, 담당자 표시·미등록 이름 안내는 WRITING.md/TERMS.md 기준으로 직접 검토한다.

## 운영 반영

서버 수정만 필요하다. 기존 담당자/멘션 명부를 다시 입력하거나 앱을 재설치할 필요는 없다. 운영 반영 결과는 인프라 담당 배포 보고서로 별도 기록한다.
