# 예약 업무 v1

## 범위

프로젝트의 최신 할 일을 지정한 요일·시각(Asia/Seoul)에 조회하여 담당자별 마감 안내를 Google Chat으로 보내거나 홈과 앱 알림으로 전달한다. 오전 안내 뒤 같은 날 후속 확인 시각에는 실제로 안내한 일 중 아직 조건에 해당하는 미완료 일만 다시 확인한다.

## 계약

- 예약: 소유자, 워크스페이스, 선택 프로젝트, 이름, 요일(월=1), 시각, 선택 후속 시각, 할 일 범위, 기한 지난 일 포함 여부, 담당자 필터, 전달 위치, 멘션 설정, 활성 상태, 다음 실행, 낙관적 버전.
- Google Chat은 해당 프로젝트의 활성 웹훅만 사용한다. 다른 워크스페이스·프로젝트의 연결을 사용할 수 없다.
- 등록·변경 시 미리보기로 실제 대상과 메시지를 확인한다. 대화에서 작성한 초안도 같은 관리 화면에서 활성화한다.
- 저장된 문장을 재생하지 않고 실행 시점의 데이터로 조회한다. 완료·취소한 일은 제외한다. 날짜는 한국 날짜의 자정 경계로 비교한다.
- 쉼표로 구분된 공동 담당자는 공백·빈 항목·중복을 정리한 뒤 각각 멘션 디렉터리에서 확인한다. 담당자 필터는 한 명이라도 일치하면 해당 일을 한 번만 포함하며, 안내에는 공동 담당자 모두를 개별 멘션한다. 기존 일감의 담당자 저장값은 변경하지 않는다.
- 실행 슬롯은 유일하며 서버 재시작·중복 worker가 중복 실행을 만들지 않는다. 수동 실행은 별도 요청 ID로 멱등 처리한다.
- 2시간 이내 놓친 실행은 최신 데이터로 복구한다. 그보다 오래된 실행은 건너뛰고 다음 미래 실행을 계산한다. 과거 슬롯을 몰아서 발송하지 않는다.
- 예약 변경·일시정지·삭제는 아직 발송하지 않은 실행을 취소한다. 이미 외부 전송을 시작한 메시지는 회수할 수 없다.
- 빈 조회는 생략으로 기록한다. 조회 실패·멘션 매핑 누락·전송 실패는 빈 결과로 처리하지 않는다.
- 외부 전송은 기존 durable webhook outbox와 재시도를 사용한다. 원격 서버가 성공 응답 전에 연결을 끊는 경우 exactly-once 전달을 보장할 수 없으므로 실행·전달 이력을 남긴다.
- 긴 안내는 담당자와 일감 단위로 나눠 1,800자 한도를 지킨다. 일부 항목을 조용히 누락하지 않는다.
- 비공개 원문 대신 일감의 검토된 배정 내용·참고 링크를 우선 사용한다. 이름·날짜·링크를 임의 생성하지 않는다.

## 환경

운영 schema 55 커밋 `7a309eb` 기반의 `codex/scheduled-work`에서 개발한다. 독립 개발 DB와 서버로 검증한다. 2026-09-14 사용자가 개발 확인 이후 산출물 정리와 운영 배포를 승인했다.

## 배포 및 복구

API·Agent·클라이언트가 함께 필요한 schema 56 릴리스다. 기존 transcriber는 변경하지 않는다. 운영 DB 백업을 별도 DB에 복원해 schema 55를 확인한 뒤 exact commit의 이미지를 배포한다. migration과 health 검증이 실패하면 이전 앱 이미지·설정·DB 백업을 함께 복원한다. schema 56 DB에 schema 55 바이너리만 덮어쓰는 복구는 하지 않는다. 새 예약을 자동으로 생성하거나 사용자 확인 없이 켜지 않는다.

## 제한

- v1은 한국 시간의 주간 반복이다. 공휴일 제외·매월 규칙·다중 단계 임의 자동화는 지원하지 않는다.
- 등록된 프로젝트 연결에만 전달한다. 승인된 배정 상세와 링크를 사용하며 비공개 원문을 임의 전송하지 않는다.
- 홈의 실행 이력은 앱 알림 권한이 없어도 볼 수 있다. FCM 실제 수신은 기기 권한·네트워크에 따라 달라진다.
